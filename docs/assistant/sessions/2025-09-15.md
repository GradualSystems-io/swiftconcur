# Session 2025-09-15

## Goal & Summary
- Investigate why GitHub App installations are not reflected in the dashboard repository list.
- Identified missing post-authentication redirect handling that prevented the installation callback from running; updated login flow to honour redirect targets and respect the deployed base path to avoid `/` redirects.

- Normalized Supabase payloads, switched server-side GitHub linking to service-role Supabase clients, and relied on GitHub's installation id when syncing repositories to avoid race conditions.
- Updated client sign-out flow to detect the deployed base path and redirect to the correct `/auth/login` URL.
- Ensure repository sync populates legacy `github_id` column required by early schema.
- Explicitly set `user_id` on synced repositories so the dashboard query picks them up post-install.
- Updated client-side sync button to request the API with the deployment base path and surface non-JSON error bodies when needed.
- Added repository detail route (`repositories/[...slug]/page.tsx`) and switched detail links to Next.js `Link` so connected repos open inside the dashboard.
- Repository detail page now fetches installation metadata with a separate query, avoiding schema assumptions that triggered server errors.
- Dashboard landing page now reads from the `repositories` table so connected GitHub repos appear immediately (user_repos table still unused).
- Removed unused notification bell from header until a real notifications feed is implemented.
- Hooked the header help icon to `/docs` so users can reach the in-app documentation quickly.
