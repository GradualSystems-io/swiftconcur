# Session 2025-09-21

## Goal & Summary
- Align SwiftConcur workflow with customer setup by guarding GitHub App steps and renaming secrets to `GH_*`.
- Add dashboard support for user-managed webhook secrets, including Supabase schema changes, API routes, UI, and signature fallback logic.
- Fixed sidebar/repo card navigation to target `/repositories/[owner]/[repo]` instead of the obsolete `/r/:id` path.
- Hardened repository detail page queries and installation metadata fetch to tolerate missing `full_name` values and Supabase gaps without crashing the server route.
- Webhook secret manager now validates the presence of a GitHub installation before calling the API, preventing confusing errors when the installation link is missing.
- GitHub repository sync now upserts on `user_id, github_id`, resolving duplicate-key errors when reinstalling the app for the same user.

## Key Decisions & Assumptions
- `GH_WEBHOOK_SECRET` is optional globally; per-installation secrets stored in Supabase take precedence when provided.
- Customers never receive `GH_APP_ID` / `GH_APP_PRIVATE_KEY`; workflows must succeed without those secrets present.
